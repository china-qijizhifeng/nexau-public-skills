# PAT 能做什么，什么必须管理员

**一句话**：PAT 不是「管理员钥匙」，**它就是你本人**。能做什么完全等于你这个账号的权限 ——
项目里的角色决定项目操作，账号上的管理员标志决定平台操作。

---

## 1. 三条最容易误解的

### ① 非管理员也能创建 PAT

PAT 与管理员身份**没有关系**。任何能登录控制台的账号都能自己创建 PAT，这是正常设计 ——
它是「把你的账号权限装进一个可以给脚本用的凭据」，不是「申请更高权限」。

### ② PAT 没有权限范围，只能设过期时间

创建时能填的只有**名字**和**有效期**（`7d` / `30d` / `90d` / `365d`，或不填 = 永不过期）。

⚠️ **没有 scope、没有「只读 PAT」、没有「只能部署某个项目的 PAT」。**
一把 PAT 拿到的就是你账号的全部权限。

⇒ **一把 PAT 泄露 = 你整个账号泄露**，包括你所有能访问的项目。对策只有三条：
给 CI 用的令牌**设短有效期**、**一个用途一把**（出事能精确吊销）、
`nac tokens list` 里看 `last_used_at` 定期清掉不再用的。

### ③ 管理员身份挂在账号上，不在 PAT 上

同一把 PAT，在你**被授予**管理员之后就能打管理端点，被**取消**之后立刻打不动 ——
令牌本身不用重发。⇒ 排查「这把 PAT 为什么突然 403」时，先想想账号权限是不是变了。

---

## 2. 项目级：三档权限

### ⭐ 先说最容易误解的：**你自己创建的项目，你什么都能做**

**你是项目的创建者 = 你是它的 owner ⇒ 读、写、治理三档全部直接放行**，
不需要谁给你授权、不需要配任何角色、更不需要管理员。
**用你自己的 PAT 部署制品到自己项目的环境，是完全正常的日常操作。**

平台判权是**依次放行**的，命中任一条就通过：

1. **你是不是这个项目的 owner** ← 自己建的项目在这一步就过了，后面根本不看
2. 你是不是平台管理员
3. 你在这个项目里的协作角色够不够（读要 viewer+，写要 developer+）

⇒ **下面这张三档表，只在「别人的项目、你被拉进去协作」时才有意义。** 自己的项目不受它约束。

---

### 协作项目里的三档

平台对项目操作分三档，从低到高。**同一个人在不同项目里可以是不同档。**

| 档位 | 能做什么 | 典型命令 |
|---|---|---|
| **项目只读** | 看项目信息、版本列表与详情、环境列表、会话列表、trace、版本日志、制品元数据与下载 | `nac status` / `versions list` / `sessions` / `traces` / `trace` |
| **项目读写** | 上面全部，**加上**：部署、改版本、激活/停用、回滚、扩缩容、建删环境、改环境变量、管 API Key、管渠道、改 LLM 设置、看环境日志 | `nac deploy` / `vars` / `keys` / `environments` / `channels` / `llm` / `logs` |
| **项目管理者** | 上面全部，**加上**：删除项目、项目隐私域相关操作 | 控制台为主 |

⚠️ **读和写的分界不总是直觉的**，两个例子：

- **看环境日志**要**读写**档，不是只读档（`nac logs <env>`）；但**看版本日志**只要只读档。
- **列 API Key**（`nac keys list`）要**读写**档 —— 因为同一组端点也能创建和重置密钥。

## 3. CLI 命令需要哪一档

**结论先行：24 个顶层命令里，没有任何一个需要管理员。**

| 命令 | 打哪个面 | 需要 |
|---|---|---|
| `init` / `completions` | 纯本地 | 无 |
| `auth login/logout/whoami` | 管理面 | 登录即可 |
| `tokens list/create/delete` | 管理面 | 登录即可（只能管**自己**的令牌） |
| `projects list/create` | 管理面 | 登录即可（只列出你有权访问的） |
| `projects get` / `status` / `sessions` / `traces` / `trace` | 管理面 | 项目只读 |
| `versions list/get` | 管理面 | 项目只读 |
| `versions deploy/activate/deactivate/redeploy/scale` | 管理面 | 项目读写 |
| `deploy` | 管理面 | 项目读写 |
| `environments list/get` | 管理面 | 项目只读 |
| `environments create/delete/extend` / `clean` | 管理面 | 项目读写 |
| `vars` / `keys` / `channels` / `llm` | 管理面 | 项目读写 |
| `logs`（环境日志） | 管理面 | 项目读写 |
| `chat` / `smoke` / `test` / `bench` / `dev` | **对话面** | 项目 AK/SK **或** PAT + `X-Project-Id` |
| `api` | 取决于你打哪个端点 | 见下 |

⇒ **只有 `nac api` 能碰到管理员端点**，因为它是逃生舱、可以打任意路径。
其余 23 个命令没有任何一条会走到管理面的 `/api/admin/*`。

## 4. 必须管理员的事

**判据极其简单：路径以 `/api/admin/` 开头的，全部需要管理员；不以它开头的，全部不需要。**
（当前 73 个管理端点无一例外落在这个前缀下。）

CLI **没有**对应命令，只能 `nac api` 打。按功能域分八类：

| 域 | 路径前缀 | 大致是什么 |
|---|---|---|
| 跨项目视图 | `/api/admin/projects`、`/api/admin/project-owners`、`/api/admin/audit/*` | 列出**全平台**的项目和归属人、审计查询 |
| 运营看板 | `/api/admin/summary/*` | 用量、趋势、事故、用户、规模、模型指标 |
| 平台 LLM 目录 | `/api/admin/llm-providers/*`、`/api/admin/llm-models/*` | 增删改供应商与模型卡、设平台默认模型、给某项目解锁模型 |
| 版本运维 | `/api/admin/versions/{id}/*` | 强制拉起 / 停止某个版本的实例、查实例明细 |
| 弹性与容量 | `/api/admin/autoscaling*`、`/api/admin/resource-ceiling`、`/api/admin/scale-pin` | 平台级扩缩预设、资源上限、固定副本数 |
| 出网安全 | `/api/admin/safenetwork*` | 平台默认出网策略、拦截豁免、代理启停、CA 刷新 |
| 隐私域与密钥 | `/api/admin/privacy-domain/*` | 部门密钥、KMS 端点、项目主密钥、rekey、加密审计 |
| 平台资产 | `/api/admin/builtin-agents/*`、`/api/admin/resource-catalog/*`、`/api/admin/ocr-configs/*` | 内置 agent 与服务包、资源目录 bundle、OCR 配置 |

⚠️ **这些是平台运营的旋钮，不是「高级用法」。** 作为平台使用者，
正常开发部署链路一个都用不到 —— 如果你觉得需要，多半是走错了方向，先问平台方。

## 5. 403 了，怎么分清是哪一种

三种 403 长得像，处置完全不同：

| 现象 | 是什么 | 怎么办 |
|---|---|---|
| message 里出现 `AK/SK credentials are valid only on the data plane` | **拿错凭据**：AK/SK 打了管理面 | 换 PAT。见 `SKILL.md` §1 |
| 打 `/api/admin/*` 被拒 | **你不是管理员** | 这不是你该做的操作，找平台方 |
| 打普通项目端点被拒 | **你在这个项目里的档位不够**（比如只读档想部署）。⚠️ 只可能发生在**别人的项目**上 —— 自己创建的项目你是 owner，不会因为档位被拒 | 找项目 owner 提权 |

自检顺序：

```bash
nac api GET /api/auth/me --json      # ① 令牌属于这个平台吗（200 = 是，401 = 地址或令牌不对）
nac projects list                     # ② 这个项目在不在我的可见列表里（不在 = 根本没权限）
nac tokens list                       # ③ 这把令牌过期没有、上次用是什么时候
```

⚠️ **`nac auth whoami` 不验证平台，也不会告诉你「你是不是管理员」，也不会告诉你在某个项目里是哪一档。**
档位只能通过「某个操作成不成」反推，或者问项目 owner。

⚠️ **在自己创建的项目上被拒，几乎一定不是档位问题** —— 先按上表查前两行（凭据拿错、打了 admin 路径），
再看是不是项目被软删了（软删项目的写操作和治理操作会被直接拒绝，读还能过）。
